# HPE Aruba Networking Central — Routing Protocol Analysis

Deep-dive into routing protocol operation on Aruba gateways and VPN concentrators. Retrieve BGP peer tables and RIB for 11-step best-path analysis, inspect OSPF adjacencies and Link State Database (LSDB) for LSA-type analysis, and query the full IP routing table with protocol-level filtering.

## Tools (4)

### BGP Analysis (2 tools)

| Tool | Parameters | Description |
|------|-----------|-------------|
| `aruba_get_bgp_neighbors` | `serial` (required) | Get BGP peer table — neighbor IPs, remote AS, BGP state (Established/Idle/Active), hold timer, uptime, prefixes received/sent |
| `aruba_get_bgp_routes` | `serial` (required), `prefix` (optional CIDR filter), `limit` (default 100), `offset` (default 0) | Get BGP RIB — prefixes, next-hops, AS paths, LOCAL_PREF, MED, communities, and best-path selection attributes |

### OSPF Analysis (2 tools)

| Tool | Parameters | Description |
|------|-----------|-------------|
| `aruba_get_ospf_neighbors` | `serial` (required) | Get OSPF neighbor table — neighbor router IDs, states (FULL/LOADING/EXCHANGE), areas, interfaces, priority, and dead intervals |
| `aruba_get_ospf_lsdb` | `serial` (required), `area_id` (optional, e.g. '0.0.0.0') | Get OSPF Link State Database — all LSAs with type (1=Router, 2=Network, 3=Summary, 4=ASBR-Summary, 5=AS-External, 7=NSSA), originator, sequence, and age |

## BGP Best-Path Selection (11 Steps)

When analyzing BGP routes from `aruba_get_bgp_routes`, apply the standard 11-step decision process to identify why a specific path is selected as best:

| Step | Attribute | Preference |
|------|-----------|-----------|
| 1 | **Next-hop reachability** | Discard routes with unreachable next-hops |
| 2 | **Weight** (Cisco proprietary) | Higher weight wins (locally significant) |
| 3 | **LOCAL_PREF** | Higher value wins (intra-AS preference) |
| 4 | **Locally originated** | Prefer routes originated by this router (network/aggregate) |
| 5 | **AS_PATH length** | Shorter AS path wins |
| 6 | **Origin code** | IGP (i) > EGP (e) > Incomplete (?) |
| 7 | **MED (MULTI_EXIT_DISC)** | Lower MED wins (comparable between same AS only) |
| 8 | **eBGP vs iBGP** | Prefer eBGP routes over iBGP routes |
| 9 | **IGP metric to next-hop** | Lower IGP cost to next-hop wins |
| 10 | **Oldest eBGP route** | Prefer most stable (oldest) eBGP route |
| 11 | **Lowest BGP Router ID** | Tiebreaker — prefer lowest router ID |

## OSPF LSA Types Reference

When analyzing OSPF LSDB from `aruba_get_ospf_lsdb`:

| LSA Type | Name | Purpose |
|----------|------|---------|
| Type 1 | **Router LSA** | Each router's directly connected links and costs |
| Type 2 | **Network LSA** | Multi-access network segment (generated by DR) |
| Type 3 | **Summary LSA** | Inter-area route summary (generated by ABR) |
| Type 4 | **ASBR Summary LSA** | Reachability of ASBR (generated by ABR) |
| Type 5 | **AS External LSA** | External routes redistributed into OSPF (generated by ASBR) |
| Type 7 | **NSSA External LSA** | External routes in Not-So-Stubby Areas |

## Workflows

### 1. BGP Health Check
```
aruba_get_bgp_neighbors(serial) → list all BGP peers
→ Identify peers NOT in Established state (Idle, Active, OpenSent, etc.)
→ For non-Established peers: check hold timer expiry, uptime, prefix count
→ aruba_get_bgp_routes(serial) → verify expected prefixes are in the RIB
→ If prefixes missing: check AS path, LOCAL_PREF, and route policy filtering
→ GAIT
```

### 2. BGP Best-Path Analysis
```
aruba_get_bgp_routes(serial, prefix="x.x.x.x/y") → get all paths for a specific prefix
→ Apply 11-step best-path selection:
   Step 5: Compare AS_PATH lengths → prefer shortest
   Step 3: Compare LOCAL_PREF → prefer highest
   Step 7: Compare MED → prefer lowest (same AS only)
   Step 8: eBGP > iBGP
→ Verify best path matches expected traffic path
→ If sub-optimal: identify which attribute needs tuning (LOCAL_PREF, MED, route-map)
→ GAIT
```

### 3. BGP Route Leak / Hijack Detection
```
aruba_get_bgp_routes(serial) → retrieve full BGP RIB
→ Identify unexpected AS paths (routes via unexpected upstream AS)
→ Check for more-specific prefixes (prefix hijacking indicator)
→ Verify BGP communities are correct per policy
→ Correlate with NVD CVE for BGP-related vulnerabilities in current firmware
→ GAIT
```

### 4. OSPF Adjacency Audit
```
aruba_get_ospf_neighbors(serial) → list all OSPF neighbors
→ Verify all expected neighbors are in FULL state
→ Identify neighbors stuck in: ATTEMPT, INIT, 2WAY, EXSTART, EXCHANGE, LOADING
  → Non-FULL state indicates authentication, MTU mismatch, area mismatch, or timer mismatch
→ Check DR/BDR election status on multi-access segments
→ GAIT
```

### 5. OSPF LSDB Analysis
```
aruba_get_ospf_lsdb(serial) → retrieve full LSDB
→ Count LSAs by type: Type 1 (topology), Type 3 (inter-area), Type 5 (external)
→ Check LSA sequence numbers for stuck/premature aging (MaxAge = 3600)
→ Identify Type 5 LSAs from unexpected ASBRs (potential route injection)
→ aruba_get_ospf_lsdb(serial, area_id="0.0.0.0") → validate area 0 topology
→ GAIT
```

### 6. Routing Protocol Redistribution Audit
```
aruba_get_bgp_routes(serial) → check for BGP routes with OSPF origin or unexpected AS paths
→ aruba_get_ospf_lsdb(serial) → check for Type 5 LSAs (external routes from redistribution)
→ aruba_get_routing_table(serial, protocol="ospf") → check OSPF routes in RIB
→ aruba_get_routing_table(serial, protocol="bgp") → check BGP routes in RIB
→ Identify: redistribution loops, route feedback, unexpected metric values
→ GAIT
```

### 7. OSPF Area Design Review
```
aruba_get_ospf_neighbors(serial) → identify which areas this gateway participates in
→ aruba_get_ospf_lsdb(serial, area_id="0.0.0.0") → backbone area LSA count
→ For each non-backbone area: aruba_get_ospf_lsdb(serial, area_id=X)
→ Check for: oversized areas (>200 Type 1 LSAs), missing Type 3 summaries (stub/NSSA issue),
  excessive Type 5 LSAs (unfiltered external redistribution)
→ GAIT
```

## Guardrails

- **Always check BGP neighbor state before RIB analysis** — a non-Established peer means the RIB data may be incomplete or stale
- **Validate serial numbers** — gateway serial must be alphanumeric, 4–20 characters (e.g. `CN12345678`)
- **Validate CIDR prefixes** — when filtering by prefix, use valid CIDR notation (e.g. `10.0.0.0/8`)
- **OSPF LSDB is read-only** — no configuration changes are possible via this MCP server; all changes require a ServiceNow CR and pyATS/CLI
- **BGP tools apply to gateways only** — switches and APs do not run BGP; pass gateway serial numbers only
- **MED comparison is AS-scoped** — when analyzing MED (step 7 of best-path), only compare MEDs from the same neighboring AS
- **MaxAge LSAs indicate issues** — OSPF LSAs with age=3600 are being flushed; correlate with aruba_get_ospf_neighbors to find the originating router
- **Record in GAIT** — every BGP neighbor query, RIB lookup, OSPF neighbor check, and LSDB retrieval must be logged
